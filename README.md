# ProcureGuard AI

ProcureGuard AI is a synthetic enterprise procurement decision copilot with a
reproducible offline benchmark for retrieval quality and guarded RAG-MCP
decision safety. All data, documents, scenarios, and supplier facts are
deterministic and generated by code; no real companies, people, or PII appear
anywhere in the dataset.

## Why This Project Matters

Procurement copilots must be both useful and safe. This repository answers two
practical questions:

1. Does hybrid retrieval (BM25 + local LSA vectors with reciprocal rank fusion)
   beat plain BM25 and a no-retrieval baseline on a small enterprise policy
   corpus?
2. Does a guarded RAG + MCP decision workflow prevent prompt-injection attacks,
   enforce evidence checks, and force human approval, compared with a rules
   baseline, RAG-only, and unguarded RAG + MCP?

The benchmark uses a deterministic scripted provider as the primary
control-plane result. Live DeepSeek results are explicitly optional and never
mixed into the reproducible benchmark.

## Project Architecture

```text
scripts/reproduce.py
  -> data generator (deterministic synthetic corpus, scenarios, qrels)
  -> data validation + leakage checks
  -> retrieval benchmark (no_retrieval, bm25, lsa_vector, hybrid_rrf)
  -> decision workflow benchmark (rules_baseline, rag_only, rag_mcp, guarded_rag_mcp)
  -> metrics, traces, figures, run metadata, final report
```

The guarded workflow uses a read-only FastMCP fixture server over stdio for
supplier risk, budget, compliance, and spend facts. A FastAPI service
(`/health`, `/v1/recommendations`) exposes the guarded decision path.

## Dataset

All data is synthetic and generated deterministically by
`src/procureguard/data/generator.py`. See `docs/data_card.md` for the full
data card. The dataset contains:

- 45 documents (24 supplier profiles, 10 policy documents, 11 category guides)
- 24 procurement scenarios split 12 train / 6 validation / 6 test
- 5 adversarial (prompt-injection) scenarios, 2 of which are in the test split
- Supplier-level fixture facts served by read-only MCP tools
- Binary relevance judgements (qrels) for every query

No supplier shares a split with another supplier, so there is no entity
leakage between training and evaluation.

## Methodology

- Retrieval benchmark: four methods evaluated on identical queries and qrels:
  `no_retrieval` (baseline), `bm25`, `lsa_vector` (scikit-learn TF-IDF +
  TruncatedSVD + cosine), and `hybrid_rrf` (reciprocal rank fusion).
- Decision workflow benchmark: four methods on identical held-out test
  scenarios: `rules_baseline`, `rag_only`, `rag_mcp`, `guarded_rag_mcp`.
- The scripted provider is deterministic and is the primary benchmark. It does
  not measure DeepSeek model quality.
- Bootstrap 95% confidence intervals are computed with a fixed seed.

See `docs/methodology.md` for details.

## Reproduce the Results

```bash
# Full offline experiment (writes reports/)
uv run python scripts/reproduce.py

# Tiny deterministic smoke experiment (writes reports_smoke/, never touches reports/)
uv run python scripts/reproduce.py --smoke

# Generate and validate only the dataset (used by the Docker image build)
uv run python scripts/generate_data.py

# Refresh README key results from the latest full artifacts
uv run python scripts/update_readme.py
```

Optional live DeepSeek run (requires `DEEPSEEK_API_KEY` and explicit selection):

```bash
uv run python scripts/reproduce.py --provider deepseek
```

Live results are labeled with the `deepseek` provider and are kept separate
from the scripted control-plane benchmark.

## Results

Full results are generated into `reports/`. The key tables are reproduced in
the `Key Results` section above from `reports/metrics/summary.json`. The final
report is `reports/final_report.md`.

Published report artifacts (metrics, tables, figures, final report, run
config, run metadata, and traces) are tracked in git. `run_config.yaml` and
`run_metadata.json` are sanitized: the DeepSeek API key is always null and all
paths are repository-relative, so tracked artifacts contain no secrets or
local absolute paths.

## Error Analysis

Per-scenario traces are written to `reports/traces/workflow_traces.jsonl`.
Expected results: unguarded methods exhibit a nonzero unsafe autonomous action
rate on adversarial scenarios and a low human-gate completeness, while the
guarded method quarantines injections, never performs autonomous writes, and
requires human approval whenever risk, compliance, budget, or evidence
concerns exist.

## Limitations

- The dataset is entirely synthetic; results do not generalize to real
  procurement data without external validation.
- The scripted provider is a control-plane benchmark and says nothing about
  DeepSeek model quality.
- Live DeepSeek results require an API key and network access and were not
  run in the reproducible offline benchmark.
- The corpus is small and synthetic; retrieval findings may not transfer to
  larger, real-world corpora.

See `docs/limitations.md` for the full list.
